# Undercover

Entry routes `/undercover/rooms/create` and `/undercover/rooms/join`; room `/undercover/play/:code`. Real people only, up to eight. A room starts with at least `max(3, 2 × undercoverCount + whiteCount + 1)` people so the initial civilian group outnumbers undercover players. Default one undercover, zero White; configure 1–2 undercover and 0–1 White. Selecting one White requires at least four people.

## Settings and play

- Independent typing-turn and voting dropdowns: 1, 2 or 3 minutes, both default one minute. Host can update them before starting; every change resets readiness. Server owns deadlines.
- Deal words from 30 curated nearby-word pairs, with either word randomly selected as the main word. Assign roles privately. Clients receive only their own word (or null), a personal confirmed ballot and last-chance eligibility. **No role/faction of a surviving player is sent in snapshots or private messages**. Only the voted-out person's role becomes public after voting resolves. Results announce the winning faction with its portrait, plus player names, words and win/loss statuses. Individual surviving roles stay private throughout play.
- WORD: each player can reveal/hide their own word and acknowledge readiness. All ready or 60 seconds starts the first clue cycle.
- DESCRIBE: each active person gets one 1–120-character clue in seat order. Starting seat rotates each cycle. A clue equal to the secret word is rejected; players must avoid indirect spoilers themselves. A turn timeout records a missed clue and moves on.
- DISCUSS: after every active clue turn finishes (including timed-out turns), stop the clue timer and keep room chat available. Each active player presses พร้อมโหวต. Only when every remaining participant is connected and ready does the server open voting for the entire room. There is no automatic discussion timeout. Readiness survives reconnect; an expired participant is removed from the gate.
- VOTING: everyone still active chooses another active player and confirms a person-only ballot. There is no suspected-role dropdown or role in a private ballot. Confirmed ballots lock and restore after reconnect. Candidate totals stay hidden until voting resolves. All active voters confirmed or deadline triggers resolution.
- Highest vote leaves. A tie creates one runoff limited to tied candidates; another tie or no votes starts another clue cycle without eliminating anyone. Players who already left can watch, but cannot hint/vote.
- REVEAL: the eliminated player's role and portrait are shown to everyone for six seconds, using one server deadline. Only `lastVote.role` is public, never another player's role or a word. Reconnect preserves this deadline; no early winner check can interrupt the reveal. After it finishes, resolve non-White elimination or open the White last chance with a fresh full minute.
- A voted White gets a private GUESS popup with answer input, confirmation and surrender, for 60 seconds. Only that person can submit; others see a waiting popup. Correct main-word guess wins immediately for that White. Wrong guess, surrender or timeout removes them and checks the remaining game. Another participant disconnecting cannot cut off this last chance.
- The main-word group wins once all alternate-word and no-word players are out. Undercover players win once their remaining number is at least the remaining main-word number. If only no-word players remain, they win. Team wins include teammates voted out earlier. A White's correct guess takes precedence while their last-chance window is open.
- Reconnect is allowed for 60 seconds without restarting deadlines or changing confirmed ballots. On expiry, a player leaves the active round, the host transfers, invalid target ballots are cleared, and the game progresses or ends as appropriate. Rooms/scores remain in memory, as with the existing games.

## Components and data boundaries

Shared `PlayerVotingContent` (also used by Spyfall), `RoomEntryForm`, `RoomEntryTabs`, `CurrentRoomNotice`, `RoomEntryHeader`, `SpyfallSelect`, `RoomIdentity`, `GameDialog`, `BrandLogo`, clipboard handling, `GameSession` and `useDeadlineNow` are reused. `UndercoverLobby`, `UndercoverSettings`, `UnderRoster`, `UnderWord`, `UnderHistory`, `UndercoverResults` and the voting/reveal/guess dialogs keep the page controller small. One responsive DOM preserves form drafts across viewport changes. Typing and ballots use round/turn tokens and bounded per-player action replay sets.

`UndercoverRoom` reuses the existing `CardRoom` transport (rate limits, batched public snapshots, reconnect/dispose). `UndercoverGame` handles private roles/words, queues and votes with Map/Set. Public player DTOs omit role, word, expiry and replay data. Only owner-addressed `undercover` messages contain words; correct answers become public only in final results. No polling or per-second server broadcasts; only an event deadline timer, cleared at transitions/disposal. Clue history is capped at 80 entries and each player's seen-action set at 2,048 per round.

## Results design 01

`UndercoverResults` implements the approved centered victory layout: low-polygon portrait with gold laurels, large faction title, winner names and main-word pill, semantic results table, and lobby/replay plus round-summary actions. The server result reason determines the faction: `citizens` → คนธรรมดา, `undercover` → Undercover, and both `white_guess`/`last_white` → Mr. White. `not_enough_players` shows a neutral finish with no winner portrait. Every viewer sees the same winning-faction title; row statuses use the server's exact winner IDs. Gameplay and payout rules are unchanged.

`UnderRolePortrait` shares the existing cached sprite and role labels with the public vote reveal. Gold laurels/facets are SVG/CSS, requiring no additional image requests, dependencies or animation timers. The old result-list markup and CSS are removed. The page keeps actions visible at every size and lets the table scroll internally for eight-player rooms; long winner names remain accessible in their own bounded region. The summary dialog reuses `GameDialog` and `UnderHistory` to show clues, the latest vote and any final White answer. Only the connected host can prepare another round; other participants see the waiting state.

`npm run test:undercover-results` covers all winning factions and the neutral outcome, 3/8 players at 11 desktop/tablet/phone portrait/landscape sizes, long names, table scrolling, summary focus restoration, host/reconnect restrictions and the replay action. ## Gameplay design 01 with room chat

`UndercoverDiscussion` replaces the old three-column roster/history/private-word layout after WORD. A separate private composer sits above a public clue board; only the current speaker sees an editable clue field. Drafts stay in React state and are never transmitted until submitted. Cards show initials, name, seat number, connection/turn/elimination state and the submitted clue. They retain seat order rather than changing order on submission. One card per player is shown for each cycle; the shared `SpyfallSelect` switches to previous retained cycles. `UnderHistory` remains in the results summary, where the full chronological log is still useful.

The desktop board uses three columns with a chat sidebar. Tablet and phone use a bottom chat button with an unread count; its native `GameDialog` opens a bottom sheet with focus containment, Escape/close and focus return. Landscape puts the composer beside the board. Content scrolls within bounded regions at small sizes, keeping room controls and the chat action in view. Opening/closing chat and changing viewport preserve its draft. There is only one mounted message log/input at a time.

Chat is a new `chat` action on the existing room socket, independent of clue submission and the speaker's turn. Only connected, active players can send during DESCRIBE and DISCUSS. It pauses during WORD, voting, public reveal, White guessing and results; eliminated players can read but not send. The server trims and validates 1–500 characters, allows at most three messages per five seconds per player, deduplicates action IDs, retains the latest 100 messages and includes only public author/name/text/time fields. Reconnection restores that bounded history; preparing or starting a new round clears it and the rate counters. Chat does not advance a turn, alter a deadline, or count as a clue/vote. Rejected messages retain the user's draft, and accepted messages clear it after server echo. React renders message text without HTML interpretation.

The existing transport batches snapshots; there is no second socket, polling or typing broadcast. Memoized board/chat components avoid rebuilding their contents on every countdown tick. The responsive media listener and existing deadline hook clean up on unmount; message timestamps reuse one formatter. UI decoration uses CSS and the shared SVG `LobbyIcon`, requiring no new raster assets or dependencies. Retired composer/private-sidebar CSS and markup are removed. The shared role-reveal artwork remains in use. Current entry asset reuse and cleanup are documented in [room entry](room-entry.md).

`npm run test:undercover-discussion` checks 3/6/8-player boards at eleven desktop/tablet/phone portrait/landscape sizes, seat order, public clues versus private drafts, cycle selection, single-instance chat, mobile unread/focus/draft behavior, acknowledgements and escaped text. Unit/socket tests cover validation, rate/history bounds, phase restrictions, turn/deadline independence, cloning, reconnect and replay cleanup. The real four-browser regression includes chat delivery before clues and the complete vote/reveal/White/replay sequence.


## Ready-to-vote and voting design 01

After the final clue/timeout the server enters `DISCUSS` with no deadline or phase timer. The approved gold ready dock is disabled while clues are still in progress and enabled for each active, connected player once they are complete. It displays the ready count, a progress track and the viewer's confirmed state. The submitted personal clue stays visible in a read-only panel beside the private reveal/hide word control; no new clue can be sent. Chat continues. `readyVote` uses the existing round/turn/action IDs; the public `voteReadyIds` list contains only readiness, never vote targets. A Set bounds it to the room's eight participants. A disconnect keeps readiness but prevents the gate from opening until reconnect; expiry removes the participant and rechecks readiness/win conditions. Each clue cycle and replay clears it. The voting deadline starts fresh only after the gate opens.

The popup reuses `PlayerVotingContent` with optional `showClues`, `clue`, emblem and confirmation-icon props. Spyfall keeps its default layout and behavior. Undercover displays two columns of dark cards containing seat number, neutral initial, name and that player's latest clue from the current cycle. Portrait phones use one column; small/short screens scroll the candidate list internally while keeping the countdown and confirmation footer visible. The viewer's card remains readable but disabled. Selected cards use gold borders/checks; voting confirmation still locks, restores on reconnect and keeps individual choices private. Runoffs retain all active players' clues while enabling only eligible candidates. No new raster asset is used. The old ivory Undercover ballot styling is removed.

`npm run test:undercover-voting` covers 3/6/8 players at eleven sizes, disabled/confirmed/offline/spectator ready actions, readiness payloads, chat during discussion, the latest-cycle clues, self-vote restriction, confirmation locks, runoff eligibility, long names/clues and reachable 44px actions. The four-browser flow verifies no popup before all players are ready, simultaneous opening afterwards, clue visibility inside the popup and the complete White/replay sequence. Unit and WebSocket tests cover early/stale ready requests, idempotence, no automatic deadline, reconnect/expiry, new-cycle cleanup and preserved existing game rules.
