# Undercover

Entry routes `/undercover/rooms/create` and `/undercover/rooms/join`; room `/undercover/play/:code`. Real people only, up to eight. A room starts with at least `max(3, 2 × undercoverCount + whiteCount + 1)` people so the initial civilian group outnumbers undercover players. Default one undercover, zero White; configure 1–2 undercover and 0–1 White. Selecting one White requires at least four people.

## Settings and play

- Independent typing-turn and voting dropdowns: 1, 2 or 3 minutes, both default one minute. Host can update them before starting; every change resets readiness. Server owns deadlines.
- Deal words from 30 curated nearby-word pairs, with either word randomly selected as the main word. Assign roles privately. Clients receive only their own word (or null), a personal confirmed ballot and last-chance eligibility. **No role/faction of a surviving player is sent in snapshots or private messages**. Only the voted-out person's role becomes public after voting resolves. Results announce the winning faction with its portrait, plus player names, words and win/loss statuses. Individual surviving roles stay private throughout play.
- WORD: each player can reveal/hide their own word and acknowledge readiness. All ready or 60 seconds starts the first clue cycle.
- DESCRIBE: each active person gets one 1–120-character clue in seat order. Starting seat rotates each cycle. A clue equal to the secret word is rejected; players must avoid indirect spoilers themselves. A turn timeout records a missed clue and moves on.
- VOTING: everyone still active chooses another active player and confirms a person-only ballot. There is no suspected-role dropdown or role in a private ballot. Confirmed ballots lock and restore after reconnect. Candidate totals stay hidden until voting resolves. All active voters confirmed or deadline triggers resolution.
- Highest vote leaves. A tie creates one runoff limited to tied candidates; another tie or no votes starts another clue cycle without eliminating anyone. Players who already left can watch, but cannot hint/vote.
- REVEAL: the eliminated player's role and portrait are shown to everyone for six seconds, using one server deadline. Only `lastVote.role` is public, never another player's role or a word. Reconnect preserves this deadline; no early winner check can interrupt the reveal. After it finishes, resolve non-White elimination or open the White last chance with a fresh full minute.
- A voted White gets a private GUESS popup with answer input, confirmation and surrender, for 60 seconds. Only that person can submit; others see a waiting popup. Correct main-word guess wins immediately for that White. Wrong guess, surrender or timeout removes them and checks the remaining game. Another participant disconnecting cannot cut off this last chance.
- The main-word group wins once all alternate-word and no-word players are out. Undercover players win once their remaining number is at least the remaining main-word number. If only no-word players remain, they win. Team wins include teammates voted out earlier. A White's correct guess takes precedence while their last-chance window is open.
- Reconnect is allowed for 60 seconds without restarting deadlines or changing confirmed ballots. On expiry, a player leaves the active round, the host transfers, invalid target ballots are cleared, and the game progresses or ends as appropriate. Rooms/scores remain in memory, as with the existing games.

## Components and data boundaries

Shared `PlayerVotingContent` (also used by Spyfall), `RoomEntryForm`, `RoomEntryTabs`, `CurrentRoomNotice`, `GameSwitch`, `SpyfallSelect`, `RoomIdentity`, `GameDialog`, `BrandLogo`, clipboard handling, `GameSession` and `useDeadlineNow` are reused. `UndercoverLobby`, `UndercoverSettings`, `UnderRoster`, `UnderWord`, `UnderHistory`, `UndercoverResults` and the voting/reveal/guess dialogs keep the page controller small. One responsive DOM preserves form drafts across viewport changes. Typing and ballots use round/turn tokens and bounded per-player action replay sets.

`UndercoverRoom` reuses the existing `CardRoom` transport (rate limits, batched public snapshots, reconnect/dispose). `UndercoverGame` handles private roles/words, queues and votes with Map/Set. Public player DTOs omit role, word, expiry and replay data. Only owner-addressed `undercover` messages contain words; correct answers become public only in final results. No polling or per-second server broadcasts; only an event deadline timer, cleared at transitions/disposal. Clue history is capped at 80 entries and each player's seen-action set at 2,048 per round.

## Results design 01

`UndercoverResults` implements the approved centered victory layout: low-polygon portrait with gold laurels, large faction title, winner names and main-word pill, semantic results table, and lobby/replay plus round-summary actions. The server result reason determines the faction: `citizens` → คนธรรมดา, `undercover` → Undercover, and both `white_guess`/`last_white` → Mr. White. `not_enough_players` shows a neutral finish with no winner portrait. Every viewer sees the same winning-faction title; row statuses use the server's exact winner IDs. Gameplay and payout rules are unchanged.

`UnderRolePortrait` shares the existing cached sprite and role labels with the public vote reveal. Gold laurels/facets are SVG/CSS, requiring no additional image requests, dependencies or animation timers. The old result-list markup and CSS are removed. The page keeps actions visible at every size and lets the table scroll internally for eight-player rooms; long winner names remain accessible in their own bounded region. The summary dialog reuses `GameDialog` and `UnderHistory` to show clues, the latest vote and any final White answer. Only the connected host can prepare another round; other participants see the waiting state.

`npm run test:undercover-results` covers all winning factions and the neutral outcome, 3/8 players at 11 desktop/tablet/phone portrait/landscape sizes, long names, table scrolling, summary focus restoration, host/reconnect restrictions and the replay action. The existing real four-browser Undercover test verifies the White victory now uses the shared faction headline before replay.


## Lobby design 01

`UndercoverLobby` implements the approved split waiting room: two-column player cards on the left, paired time dropdowns and role counters plus a three-step overview on the right, and a fixed ready/start dock below. `UnderRoster` renders the lobby cards and decorative empty seats up to the shared eight-player limit; its active-play view stays unchanged. Lobby avatars contain initials and connection indicators only, never secret role artwork. Host/current-player labels remain visible, and the common `RoomIdentity`/copy/rules/leave controls are preserved.

`isUnderPlayerReady` is the one readiness predicate for cards, progress indicators and start eligibility: connected and either ready or host. The start requirement stays `max(3, 2 × undercoverCount + whiteCount + 1)` with every participant connected/ready. Only the connected host can edit settings or start; guests can toggle their existing ready action and see disabled settings. The page sends only the existing user actions, without additional network requests, polling, dependencies or timers. The old lobby markup and its obsolete styles are removed.

Desktop uses the reference's two-panel layout; portrait tablet/phone layouts stack into one internally scrollable content area while keeping the ready/start dock reachable. Compact landscape keeps two columns with independently scrollable roster/settings and prioritizes controls over the explanatory guide. Existing `SpyfallSelect` portals retain keyboard behavior, theme and viewport bounds when scrolling. `npm run test:undercover-lobby` checks 2/6/8 people over eleven desktop/tablet/phone sizes, empty seats, long names, connection/readiness/host transitions, all dropdown options, role counters, role-dependent minimums, and ready/start payloads. The real four-browser Undercover regression verifies the complete round and replay.
